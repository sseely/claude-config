## Observation: lizard TSX parser mis-parses function boundary around inline type-assertion braces
- **Context**: T28 removed `(user as { field?: type })` casts from
  skills/brand-knowvah/ui/Sidebar.tsx per F063.
- **Finding**: `hooks/.venv/bin/lizard` (used by hooks/check-complexity.py)
  truncates the `Sidebar` function's parsed body at line 73 (of ~155) when
  an inline TS object-type literal appears inside a type assertion in JSX
  (e.g. `(user as { credits_available?: number })`), undercounting CCN as 7.
  Removing the cast lets lizard parse the full function (37-151) and reports
  the true CCN as 13 — already over the 10-CCN hook threshold. Verified by
  reverting one cast in a scratch copy: the truncation and low CCN return
  immediately (controlled experiment, not guessed).
- **Impact**: `hooks/check-complexity.py` flagged this as an "introduced"
  violation because its baseline (git HEAD, also mis-parsed) showed CCN 7.
  The real complexity was always ~13 (masked by the parser bug); T28's
  edit did not add any branch/ternary/&&. Not fixed here — task scope is
  cast removal only (F063), and the boundary explicitly forbids leaving
  the casts in place. Flagging for a future task to either extract
  sub-render helpers in Sidebar.tsx (real fix) or add a complexity-ignore
  entry if the false-positive recurs project-wide on other TSX casts.
- **Confidence**: High (reproduced with a controlled single-line revert).
